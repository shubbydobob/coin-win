# 범위

## 프로젝트가 푸는 문제

1. 분할 진입 시 총 리스크를 진입 전에 파악할 수 없다
2. 매매 이력이 구조화되지 않아 사후 분석이 불가능하다

이 둘에 기여하지 않는 기능은 범위 밖이다.

## 매매 방식 전제

- 지지·저항 기반 양방향 (롱/숏)
- 필터: 일목균형표 구름대, 볼린저 밴드
- 증거금 약 800 USDT
- **50% 분할 진입**
- BTC 무기한 선물 (USDT 마진)

## 구현하지 않는 것

요청받아도 아래는 구현하지 않고 이 문서를 근거로 되묻는다.

### 자동 매매 / 주문 실행 API 연동
계좌 조작 권한이 필요하고, 버그의 대가가 금전 손실이다. 이 프로젝트는 계산과 기록이 목적이다.

### AI 기반 매수·매도 시점 추천, 가격 예측
구현 품질을 담보할 수 없고 검증 방법이 없다. Spring AI는 판단이 아니라 구조화와 요약에만 쓴다.

### 거래소 API Secret을 프론트엔드에 노출하는 모든 구조
바이낸스 개인 엔드포인트는 HMAC 서명이 필요해 시크릿이 클라이언트에 들어가야 한다. 정적 페이지에는 숨길 곳이 없다.

키를 쓰게 될 경우의 필수 조건:
- 읽기 전용 권한만 (Trading / Withdrawals 비활성)
- IP 화이트리스트
- 시크릿은 서버 환경변수, 브라우저는 자체 서버에만 요청

다만 시세·펀딩비·OI·롱숏비율은 **공개 엔드포인트라 키가 불필요하다.** 키로 얻는 추가 가치는 잔고 자동 입력과 실제 청산가 정도다.

Phase 3 에서 하나 더 확인됐다 — **레버리지 구간표(`/fapi/v1/leverageBracket`)도 키가 필요하다.** 서명 없이 부르면 401 이다. 그래서 구간표는 커밋된 스냅샷에서 읽는다. 키 없이 감당되는 범위가 어디까지인지가 이 문서의 전제이므로 여기에 적어 둔다.

### 실시간 뉴스 알림
매크로 발표가 가격에 반영되는 시간이 분 단위다. 헤드라인 수집 → 파싱 → 알림 → 인간 판단 → 수동 진입 경로는 구조적으로 늦다. 또한 "국채 바이백 확대 → 위험자산 상승" 같은 인과 연결은 감성분석으로 도출되지 않는다.

**대안:** 예정 이벤트 캘린더 (FOMC, CPI 등). 예측이 아니라 해당 일정에 포지션 규모를 줄이기 위한 사전 경고. Phase 8 이후 선택 구현.

### 사용자 다중 계정 / 회원가입
1인 사용 전제.

## Spring AI 적용 범위

**원칙: AI가 판단하지 않는다. 구조화와 요약만 한다.**

허용:
1. **자연어 → 매매 계획 파싱** — Structured Output. 파싱 실패 시 예외를 던지고 되묻는다. **추측해서 채우지 않는다.**
2. **백테스트 결과 요약** — 프롬프트는 `resources/prompts/`에 파일로 분리, 버전 관리
3. **매매 기록 질의 (RAG)** — pgvector. 예: 손실 직후 진입한 거래의 결과

금지:
- 매수·매도 시점 추천
- 가격 예측
- AI 응답을 근거로 한 자동 실행

이 경계를 문서화한 것 자체가 설계 판단이며, `docs/adr/005`에 기록한다.

## ADR

`docs/adr/` 아래 최소 6건 유지.

1. 단일 모듈 선택
2. **부분 헥사고날 — 왜 전면 도입하지 않았는가**
3. 도메인형 패키지 구조
4. BigDecimal 대신 값 객체
5. Spring AI 적용 범위 제한
6. 실시간 뉴스 미구현

2번이 가장 값어치 있다. 패턴을 전부 바르는 것보다, 어디에 왜 적용하지 않았는지를 설명할 수 있는 쪽이 설계 판단으로 읽힌다.
