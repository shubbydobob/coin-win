# 테스트

## 하네스 우선 (Harness-First)

**어떤 프로덕션 코드도 검증 하네스 없이 작성하지 않는다.**

작업 순서:

1. 도메인 규칙을 문장으로 서술한다 — 주석이 아니라 **테스트 이름으로**
2. 실패하는 테스트를 먼저 작성한다
3. 통과하는 **최소한의** 구현을 작성한다
4. 중복을 제거한다
5. `.\gradlew.bat check`

3번에서 "나중에 필요할 것 같은" 코드를 추가하지 않는다.

## 태스크 시작 전 출력

각 태스크를 시작하기 전 다음을 출력하고 진행한다.

```
[TASK]  무엇을 만드는가
[RULE]  이 코드가 표현하는 도메인 규칙 (한 문장)
[TEST]  먼저 작성할 테스트 이름
[TOUCH] 수정할 파일 목록
[REUSE] 재사용할 기존 코드 (없으면 "없음"이라고 명시)
```

`[REUSE] 없음`이 세 태스크 연속 나오면 멈추고 구조를 재검토한다. 중반부터는 재사용이 나와야 정상이다.

## 완료 증거

작업이 끝났다고 주장하지 않는다. **증거를 보여준다.**

- 테스트 출력 원문
- 실행한 명령과 반환값
- 빌드 종료 코드

"통과했습니다"는 증거가 아니다.

## 커버리지

- `domain` 패키지 90% 미만이면 빌드 실패 (JaCoCo)
- `adapter`는 커버리지 강제하지 않음 — 계약 테스트로 대체

## 테스트 종류별 기준

**도메인 단위 테스트**
- Spring 컨텍스트 로드 금지. 순수 JUnit
- 밀리초 단위로 끝나야 한다
- 값 객체는 반올림 경계값, 음수, 0 나눗셈, 스케일 유지를 반드시 포함

**계약 테스트 (포트)**
- 하나의 테스트 스위트를 **모든 어댑터 구현체에 대해** 실행한다
- 예: `LoadCandlesPort` 스위트가 binance / persistence / memory 세 어댑터 모두에서 통과해야 함
- 포트 추상화가 실제로 성립하는지 검증하는 유일한 방법

**통합 테스트**
- Testcontainers로 실제 PostgreSQL 사용. H2 금지 (방언 차이로 거짓 통과)
- 태그로 분리해 기본 `test`에서 제외, `./gradlew integrationTest`로 별도 실행

**지표 golden test**
- 알려진 입력 → 고정된 기댓값
- 트레이딩뷰 등 외부 도구 값과 일치하는지로 정확성 검증
- 워밍업 구간(일목 52개 미만) 처리 명시

**백테스트**
- 동일 파라미터 재실행 시 결과가 완전히 동일해야 한다 (결정론적)
- 난수 사용 시 시드 고정

## 테스트 이름

도메인 규칙이 문장으로 읽혀야 한다.

```java
// 나쁨
void testCalculate()

// 좋음
void 롱_포지션은_손절가가_최저_진입가보다_낮아야_한다()
void 분할_1차만_체결된_상태의_청산가는_전량_체결과_다르다()
```
