# CoinWin

**한 사람이 쓰는 비트코인 선물 매매 보조 도구.** 진입 전에 위험의 크기를 알고, 매매 뒤에
무슨 일이 있었는지 되짚고, **믿고 있는 규칙이 실제로 통하는지 재는 것**까지가 범위다.

주문을 내지 않는다. 사고팔 시점을 추천하지 않는다. 가격을 예측하지 않는다.

---

## 왜 만들었나

한 번의 손실이 이 프로젝트의 첫 장에 박혀 있다.

> 64,000 에 숏. **명목 9,142** — 원금 2,900 의 **3.15배**. 손절 없음.
> 78,000 까지 올라가는 동안 버티다 **−2,000**.

분해해 보면 방향을 틀린 것이 가장 큰 잘못이 아니었다. **명목만 제대로 잡았어도** 손절을 못
지킨 채 버텼을 때조차 −580 이고, 손절까지 지켰으면 −58 이다. 그래서 이 도구가 가장 먼저
답하는 질문은 "어느 쪽인가" 가 아니라 **"얼마를 걸고 있는가"** 다.

## 화면 셋

| 탭 | 답하는 질문 |
|---|---|
| **지금** | 지금 무슨 일이 벌어지고 있나 — 내 포지션, 지표 판독, 호가·이상치·예정 이벤트 |
| **매매** | 얼마를 걸고 무엇을 했나 — 포지션 계획(사이징·분할·청산가), 매매 기록과 집계 |
| **검증** | 이 규칙이 통하나 — 백테스트, 목표 복리 계산기 |

### 지금 — 내 자리

거래소의 실제 포지션과 **기록을 나란히 놓는다.** 덮어쓰지 않는 것이 요점이다 — 거래소 값으로
덮으면 "청산을 안 적었다" · "앱 밖에서 열었다" · "물타기가 안 적혔다" 가 전부 사라지고 화면은
언제나 맞는 것처럼 보인다. 이 기능은 **첫 실행에서 기록에 없는 숏 0.114 를 잡아냈다.**

평단 · 명목 · 증거금 · 레버리지 · 청산가와 **청산까지 사라지는 돈**을 함께 적는다.

### 지금 — 지표

15분 · 1시간 · 4시간(그리고 일봉 · 주봉)에서 지금 가격이 어디에 서 있나. 일목 · 볼린저 ·
RSI · MACD · 이동평균 다섯을 **추세 / 되돌림 두 무리로 갈라** 세고, **합친 수는 만들지
않는다** — 종가가 밴드 상단 위인 것은 되돌림에게 과열이고 추세에게 돌파인데 둘 다 「위」로
적히기 때문이다.

위치 딱지가 접어 버리는 값도 함께 낸다: 구름 두께·방향, 전환−기준 간격, 기준선까지 거리,
후행스팬, 밴드 안 위치(0=하단·1=상단), 밴드폭 순위, 밴드 밖 연속 봉, RSI 값과 3봉 변화,
MACD 히스토그램·영선·이어진 봉, 20−200 간격. **거리는 전부 ATR 배수**다 — 같은 300 도
조용한 장과 급한 장에서 뜻이 다르다.

### 지금 — 시장

호가(웹소켓, 100ms) · 스프레드 · 두꺼운 단, 펀딩비 · 미결제약정 · 롱숏비율 · 테이커 비율이
최근 표본에서 **어느 분위이고 어느 방향으로 움직이는 중인가**, 예정 이벤트(FOMC · CPI · QRA),
거래소 공지, 거시 자산 다섯.

**위치만으로는 모자란다.** 숏 스퀴즈는 미결제약정이 급감할 때 벌어지는데 위치만 보면 「높음」
에 머물러 있을 수 있다 — 실측에서 상위 96.7%(높음)인데 최근 30분 변화가 **−0.72%(줄어드는
중)** 인 모양이 실제로 나왔다.

### 매매 — 계획

분할 진입에서 **전량 체결 전에 총 위험을 알 수 있게** 한다. 1차만 체결된 상태와 전량 체결
상태의 평단 · 청산가 · 최대손실이 각각 다르게 나온다. 청산가는 근사식이 아니라 **거래소
공개 공식 + 커밋된 구간표**로 푼다.

### 검증 — 백테스트와 복리

지지·저항 기반 양방향 전략을 분할 진입·수수료·슬리피지까지 넣어 돌린다. 복리 화면은 묻는
방향이 반대다 — 승률·손익비를 넣고 결과를 보는 것이 아니라 **월 목표를 넣고 거래 한 건에
무엇이 필요한지**를 낸다.

거기서 나온 수 하나: 기본값(800 USDT · 월 5% · 12개월 · 10배 · 투입 20% · 월 20건)에서
**거래소에 내는 총액이 729.88** 이다. 레버리지는 수수료를 증거금이 아니라 **명목**에 붙이므로,
필요한 가격 변동을 줄이는 만큼 비용의 몫을 키운다. 두 수를 따로 보면 그 맞바꿈이 보이지 않는다.

## 이 저장소가 실제로 잰 것

**이 프로젝트의 특징은 기능 목록이 아니라 「무엇이 반증됐는가」가 문서로 남아 있다는 것이다.**

### 지지·저항 반전 전략에는 구간 밖 엣지가 없다 (`docs/adr/021`)

BTCUSDT 상장 이후 4시간봉 **15,110봉**(7년), 파라미터 18조합.

- **18조합 전부 손익비 1 미만.** 그중 여섯은 계좌를 완전히 태웠다(낙폭 100% 초과).
- anchored walk-forward **5폴드 전부 검증 실패.** 학습에서 1.00~1.14 이던 조합이 검증에서
  0.61~0.84 다. 방향이 한 번도 반대로 나오지 않았다.
- 1시간 · 4시간 · 일봉 **세 주기 전부 1 미만.**
- 8개월 표에서 "최고" 였던 조합(손익비 1.33)은 7년에서 **0.80** 이다.

### 화면의 네 지표는 비용과 시대를 함께 넘지 못한다 (`docs/adr/022`)

6년 **21만 슬롯**, 라벨 63만 행. 69개 지표 × 3 국면 × 3 기간 = **2,622줄.**

| 국면 | 1시간 | 4시간 | 24시간 |
|---|---|---|---|
| 전 구간 | **0** | **0** | 4 |
| 평균회귀 (~2024-02) | **0** | **0** | 18 |
| 모멘텀 (2024-03~) | **0** | **0** | 9 |

- **진입을 실제로 판단하는 1시간·4시간에서 여섯 번의 실행 모두 유효 후보가 0이다.** 승률로
  유의한 줄은 수백 개인데(21만 슬롯에서는 0.3%p 도 p 가 0 이 된다) **왕복 비용 0.14% 를
  넘는 것이 하나도 없다.**
- **두 시대를 함께 통과한 지표가 없다.** 겹치는 이름 하나도 시대마다 칸이 옮겨가고, 전 구간
  에서는 어느 칸도 비용을 못 넘는다.
- 유효 후보 31줄이 **전부 24시간 기간**인데, 10배에서 손절 없이 24시간을 들면 **2.056%,
  50번에 한 번이 청산**이다.

### 거래소 파생 통계도 마찬가지였다

테이커 매수/매도 비율은 승률 우위 +4.38%p 로 기준을 **통과했는데** 금액에서 졌다 — 그 분위의
평균 수익률이 +0.0516%, 왕복 비용이 0.14% 다. **승률 61.98% 인 칸도 진다.**
그리고 2024-03 에 관계의 **부호가 뒤집힌다** — 2020~2023 은 평균회귀, 2024~2026 은 모멘텀이고
크기가 다섯 배 다르다. 전 구간 평균은 어느 시대의 값도 아니다.

> **그래서 화면은 방향을 말하지 않는다.** 지표를 지우지도 않는다 — 측정이 말하는 것은
> **"이 규칙을 코드에 박지 말라"** 이지 **"보지 말라"** 가 아니다. 도구가 "이렇게 하라" 고
> 말하는 것과 사람이 그것을 보고 결정하는 것은 다른 일이다.

## 하지 않는 것

요청받아도 구현하지 않고 되묻는다. 근거는 `.claude/docs/scope.md`.

| | 왜 |
|---|---|
| 자동 매매 · 주문 실행 | 버그의 대가가 금전 손실이다. 이 도구는 계산과 기록이 목적이다 |
| AI 매수·매도 추천 · 가격 예측 | 품질을 담보할 수 없고 검증 방법이 없다 |
| API Secret 프론트 노출 | 서명이 필요한 호출은 서버에서만. 키는 읽기 전용으로 발급한다 |
| 실시간 뉴스 알림 | 헤드라인 → 파싱 → 알림 → 사람 판단 경로가 구조적으로 늦다. 대안이 예정 이벤트 캘린더다 |
| 다중 계정 · 회원가입 | 1인 사용 전제 |

AI 는 **판단하지 않고 구조화와 요약만** 한다 — 자연어를 계획으로 파싱, 백테스트 결과 요약,
매매 기록 질의(RAG). 출력 규칙은 전부 도메인 생성자에 박혀 있어 **빈 칸이 있는 계획, 원본에
없는 수를 쓴 요약, 검색되지 않은 거래를 인용한 답은 존재할 수 없다.**

## 돌리는 법

```powershell
docker compose up -d db          # PostgreSQL (pgvector)
.\gradlew.bat bootRun            # 백엔드 8080
cd frontend; npm run dev         # 화면 5173 (8080 으로 프록시)
```

**자바를 고쳤으면 `bootRun` 을 다시 띄운다.** 돌고 있는 JVM 은 클래스를 갈아 끼우지 않는다 —
그 자리에서 두 번 데였고, 지금은 화면이 흰 화면 대신 그 사실을 적는다.

거래소 키는 `.env` 로 받는다(읽기 전용 권한). **없어도 앱은 그대로 뜨고** 계좌 대조
엔드포인트만 503 이며 화면이 필요한 환경변수 이름을 말한다.

## 게이트

```powershell
.\gradlew.bat check              # 테스트 + 정적분석 + ArchUnit + 커버리지 + 프론트
```

통과했다고 말하지 않고 **출력을 보여준다.** 이 게이트가 지키는 것들:

- **ArchUnit 6규칙** — 도메인에 Spring/JPA/Jackson 금지, 계층 방향, 순환 참조 0,
  응용 계층이 어댑터를 모를 것, 백테스트가 거래소 코드를 모를 것, 아웃바운드 어댑터가
  포트를 구현할 것. **여섯 규칙 모두 상주 위반 픽스처가 실제로 발동시키는 것을 확인한다.**
- **복잡도** — 메서드 20줄 · 클래스 200줄 · 파라미터 4개 · 순환 복잡도 8 · 중첩 3.
- **도메인 커버리지 90%** 미만이면 실패.
- **스키마가 거짓말하지 않는지** — 응답 필드는 전부 `required`, 2xx 응답 선언, DTO 단순명
  충돌 금지, null 이 오는 필드는 손으로 적은 전수 목록에만.

게이트 밖(사람이 부른다):

| 명령 | 무엇 |
|---|---|
| `gradlew crossCheck` | 실제 캔들의 지표값·전략 감도표를 찍는다. 트레이딩뷰와 눈으로 대조 |
| `gradlew indicatorDump` | 6년치 봉마다 지표 칸을 CSV 로 (연구가 읽는다) |
| `gradlew integrationTest` | Testcontainers 로 진짜 PostgreSQL |
| `gradlew liveAi` | 실제 모델 호출 (키가 있을 때) |
| `gradlew openApiSchema` | 자바 DTO → `openapi.json` → 프론트 타입 재생성 |

## 구조

Java 21 · Spring Boot 4.1 · PostgreSQL(pgvector) · React 19 + TypeScript + Vite ·
lightweight-charts. 소스 397 · 자바 테스트 157 · 프론트 테스트 15 파일.

**부분 헥사고날** — 구현체가 둘 이상 있거나 있을 예정인 모듈만 포트를 갖는다.

| 모듈 | 무엇 | 방식 |
|---|---|---|
| `common` | 값 객체 (Money · Price · Quantity · Percentage · Won · ExchangeRate) | — |
| `market` | 캔들 · 펀딩비 · OI · 호가 · 환율 | 포트/어댑터 |
| `indicator` | 일목 · 볼린저 · RSI · MACD · 이동평균 · ATR · 매물대 | 계층형 |
| `position` | 사이징 · 분할 진입 · 청산가 | 계층형 |
| `projection` | 복리 · 몬테카를로 | 계층형 |
| `backtest` | 대 · 전략 · 엔진 | 계층형 |
| `journal` | 계획 → 체결 → 청산, 집계 | 포트/어댑터 |
| `account` | 거래소 포지션 대조 (서명) | 포트/어댑터 |
| `watch` | 예정 이벤트 · 거래소 공지 | 포트/어댑터 |
| `readout` | 여러 주기를 한 시각 기준으로 판독 | 계층형 |
| `ai` | 계획 파싱 · 요약 · 기록 질의 | 포트/어댑터 |

**금액·가격 계산은 값 객체로만** 하고 `BigDecimal` 을 도메인 밖에 노출하지 않는다.
**계산은 도메인이 한다** — `service.calculateX(plan)` 이 아니라 `plan.x()`.
**프론트는 숫자를 만들지 않는다**(`docs/adr/020`) — 반올림·합산·비율은 전부 서버가 낸 값이다.

## 연구 파이프라인 (`research/`)

앱과 분리돼 있고 `gradlew check` 가 보지 않는다. 게이트는 `python test_guards.py` 하나
(현재 **35 통과**). 데이터는 SQLite 하나에만 쌓이고 어디로도 나가지 않는다.

- 1분봉 **315만 행**(2020-09-01~, 구멍 0), 15분 스냅샷 **21만 행**, 라벨 **63만 행**
- 룩어헤드를 세 겹으로 막고 **저장이 전수로 다시 검사**한다
- 판정 기준은 **분석 전에** `config.py` 에 박는다 — 표본 1,000 · BH 보정 후 p<0.05 ·
  승률 +3%p · 상관 0.7 · **왕복 비용 0.14%**. 결과를 보고 고치지 않는다
- **위반 픽스처가 규칙마다 있다** — 검사가 있다는 것과 막는다는 것은 다른 사실이다

**바이낸스 월별 덤프에 틀린 분이 있다.** 실제로 거래가 있었는데 거래량 0 인 평평한 봉으로
들어온 분이 369개였고, 그 위에서 지표를 계산하면 차트에 없는 봉이 일목과 볼린저에 들어간다.
`repair.py` 가 REST 로 고친다 — 고친 뒤 라벨 커버리지가 99.9% → **100.0%** 가 됐다.

같은 자리에서 나왔다 — 전부 "이 문장이 코드에서 무엇이 되는가" 를 물었을 때다.

---

## 남아 있는 위험

**이 도구는 손실을 막지 않는다.** 막는 것은 계획 화면의 사이징이고, 그것도 사람이 그 수를
따를 때만이다. 지표를 더 잘 읽는 것과 잃지 않는 것은 다른 문제이며, **이 저장소가 지금까지
확인한 것은 앞쪽이 뒤쪽을 대신하지 못한다는 사실이다.**

그리고 **자동 테스트가 초록인 것이 화면이 맞다는 뜻이 아니다.** 이 저장소는 거짓 초록을 네 번
잡았고(`findByText` 가 필터 옵션을 잡은 것, `aria-label` 이 겹친 것, DTO 이름 충돌로 스키마가
덮인 것, 키를 `.env` 로 옮기자 live 테스트 11개가 조용히 SKIPPED 된 것) **전부 사람이 한 번
띄워 보거나 다른 테스트가 깨지면서 드러났다.**
