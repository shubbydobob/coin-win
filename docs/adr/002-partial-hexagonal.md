# ADR 002 — 부분 헥사고날: 왜 전면 도입하지 않았는가

- 상태: 채택
- 날짜: 2026-08-21

## 맥락

헥사고날(포트/어댑터)은 도메인을 외부 기술로부터 격리한다. 흔한 적용 방식은
**모든 모듈에 일괄 적용**하는 것이다. 이 프로젝트는 그렇게 하지 않는다.

## 결정

**구현체가 둘 이상 존재하거나 존재할 예정인 모듈에만 포트를 정의한다.**

| 모듈 | 방식 | 근거 |
|---|---|---|
| `market` | 포트/어댑터 | 캔들 소스가 셋 — 실시간 API / 저장된 과거 데이터 / 테스트용 인메모리 |
| `journal` | 포트/어댑터 | DB 없이 애플리케이션 서비스 테스트를 돌리려면 인메모리 어댑터가 필요 |
| `position` | 계층형 | 외부 의존 없음. 순수 계산 |
| `indicator` | 계층형 | 외부 의존 없음. 순수 함수 |
| `projection` | 계층형 | 외부 의존 없음 |
| `backtest` | 계층형 | `market` 포트를 **소비하는** 쪽. 자체 포트가 필요 없다 |

## 근거

포트는 공짜가 아니다. 인터페이스 하나마다 구현 클래스, 매핑, 테스트 더블, 탐색 비용이 붙는다.
이 비용은 **구현체를 갈아끼울 수 있다**는 이득과 교환하는 것인데, 구현체가 하나뿐이면
교환할 것이 없고 비용만 남는다.

이 프로젝트에서 포트가 실제로 값을 하는 지점은 정확히 하나다.

> `backtest` 가 백테스트 시에는 과거 캔들 어댑터를, 실사용 시에는 실시간 어댑터를
> **같은 포트로** 소비한다.

이 지점이 없었다면 전부 계층형으로 충분했다. `journal` 은 두 번째 사례로,
"DB 없이 도메인·애플리케이션 테스트를 돌린다"는 요구가 인메모리 구현체를 실제로 강제한다.

반대로 `position` 에 `PositionCalculatorPort` 같은 것을 두면, 구현체는 영원히 하나이고
테스트는 인터페이스를 거쳐 같은 클래스를 호출하게 된다. 추상화가 아니라 우회로다.

## 결과

- 모듈마다 패키지 구조가 다르다. `market`/`journal` 은 `application/port/{in,out}` 과
  `adapter/{in,out}` 을 갖고, 나머지는 `api → application → domain` 계층형이다.
  일관성이 아니라 **필요**를 기준으로 삼은 결과다.
- 이름만 헥사고날로 남는 것을 막기 위해 ArchUnit 규칙 4·5 를 둔다.
  - 규칙 4: `market.application` / `journal.application` → `adapter` 참조 금지
  - 규칙 5: `backtest` → `market.adapter` 참조 금지 (포트만 허용)

  이 둘이 없으면 서비스가 어댑터를 직접 부르기 시작하고, 포트는 장식이 된다.
- **구현체가 하나뿐인 인터페이스는 만들지 않는다**를 프로젝트 규칙으로 유지한다.
