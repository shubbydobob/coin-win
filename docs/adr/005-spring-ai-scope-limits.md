# ADR 005 — Spring AI 적용 범위 제한

- 상태: 채택
- 날짜: 2026-08-21

## 맥락

LLM 을 매매 도구에 붙이는 가장 흔한 방향은 매수·매도 시점 추천과 가격 예측이다.
Spring AI 는 이것을 기술적으로 쉽게 만든다.

## 결정

**AI 는 판단하지 않는다. 구조화와 요약만 한다.**

허용:

1. **자연어 → 매매 계획 파싱** — Structured Output.
   파싱에 실패하면 예외를 던지고 되묻는다. **추측해서 채우지 않는다.**
2. **백테스트 결과 요약** — 프롬프트는 `resources/prompts/` 에 파일로 분리하고 버전 관리한다.
3. **매매 기록 질의 (RAG)** — pgvector. 예: "손실 직후 진입한 거래의 결과".

금지:

- 매수·매도 시점 추천
- 가격 예측
- AI 응답을 근거로 한 자동 실행

## 근거

- **검증 방법이 없다.** 매매 추천의 품질은 사후 손익으로만 드러나고, 그때는 이미 돈이 나갔다.
  이 프로젝트의 다른 모든 계산(청산가, 최대 손실, 지표)은 기댓값을 고정한 테스트로 검증된다.
  추천에는 그런 하네스를 만들 방법이 없다.
- **틀린 근거가 맞는 답보다 위험하다.** LLM 이 그럴듯한 이유를 붙여 내놓는 방향 판단은,
  사용자의 원래 판단을 대체하지 않으면서 확신만 키운다.
- 반면 **구조화와 요약은 검증 가능하다.** 파싱은 입력과 기대 출력을 고정할 수 있고,
  요약은 원본 수치와 대조할 수 있다.

파싱 실패 시 추측해서 채우지 않는 것이 핵심이다. 진입가를 잘못 채운 계획은
잘못된 포지션 사이즈로 이어지고, 그 오류는 계산 계층 전체를 조용히 오염시킨다.

## 결과

- Phase 7 의 범위가 세 항목으로 고정된다. 그 밖의 요청은 이 문서를 근거로 되묻는다.
- 프롬프트가 코드가 아니라 리소스 파일이므로 변경 이력이 남는다.
