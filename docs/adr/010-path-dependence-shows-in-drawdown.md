# ADR 010 — 경로 의존성은 최종 자산이 아니라 낙폭에 나타난다

- 상태: 채택
- 날짜: 2026-08-21

## 맥락

roadmap.md 의 Phase 2 완료 조건은 이렇게 적혀 있다.

> 같은 기댓값에서도 **경로에 따라 결과가 갈리는 것**이 수치로 나온다.

이 문장을 그대로 읽으면 "승패 순서가 다르면 최종 자산이 달라진다" 를 보여주면 될 것 같다.
그런데 고정 비율 복리에서는 그것이 **성립하지 않는다.**

거래당 리스크가 현재 자산의 `r`, 손익비가 `R` 이면 각 거래는 자산에 배수를 곱한다.

```
승리: × (1 + r×R)
패배: × (1 - r)
```

`w` 승 `l` 패로 끝난 경로의 최종 자산은 순서와 무관하게 다음과 같다.

```
최종 자산 = 초기 자본 × (1 + r×R)^w × (1 - r)^l
```

곱셈은 교환법칙을 따르므로 승패 구성이 같으면 순서가 어떻든 도착점이 같다. 실제로
1000 USDT, `r` = 10%, `R` = 2 에서 `[승,패,패,승]` 과 `[패,승,승,패]` 는 **둘 다 1166.40** 이다.

| | 자산 곡선 | 최종 자산 | 최대낙폭 |
|---|---|---|---|
| `[승,패,패,승]` | 1000 → 1200 → 1080 → 972 → 1166.40 | 1166.40 | **19%** |
| `[패,승,승,패]` | 1000 → 900 → 1080 → 1296 → 1166.40 | 1166.40 | **10%** |

순서가 남기는 자국은 최종 자산이 아니라 낙폭이다.

## 결정

**분포에 최종 자산과 최대낙폭을 함께 싣는다.** `ProjectionOutcome` 은 시행 한 번에서
이 둘을 남기고, `ProjectionDistribution` 은 두 축을 **따로 정렬해** 백분위를 낸다.

```java
public record ProjectionOutcome(Money finalEquity, Percentage maxDrawdown) {}

distribution.equityPercentile(5);      // 운이 나쁠 때의 도착점
distribution.drawdownPercentile(50);   // 절반의 경우 이보다 깊게 빠진다
distribution.lossProbability();        // 초기 자본에 못 미친 시행의 비율
```

같은 시행을 최종 자산 기준과 낙폭 기준으로 각각 정렬한다. 잘 번 시행이 얌전히 갔다는
보장이 없기 때문이다.

`riskPerTrade` 는 **금액이 아니라 현재 자산의 비율**이다. 고정 금액 사이징을 택했다면 자산은
곱해지지 않고 더해져 이 ADR 자체가 성립하지 않지만, scope.md 의 전제(증거금 800 USDT, 거래당
리스크 비율로 사이징)가 비율 쪽이다.

## 근거

**첫째, 사람이 계획을 그만두는 지점은 도착점이 아니라 낙폭이다.** 최종 자산 1166.40 은 두
경로가 같지만, 두 번째 경로를 지나간 사람은 계좌가 900 까지 빠지는 것을 보고, 첫 번째 경로를
지나간 사람은 1200 을 찍은 뒤 972 까지 밀리는 것을 본다. 도착점만 보여주는 도구는
**실제로 중단을 부르는 값을 감춘다.**

**둘째, 기댓값이 같은 두 조합의 차이가 낙폭에서만 드러난다.** 승률 50% / 손익비 2 와
승률 25% / 손익비 5 는 거래당 기댓값이 둘 다 0.5R 로 같다. 최종 자산의 중앙값도 비슷하다.
갈리는 것은 낙폭 분포와 손실 확률이다 — 승률이 낮은 쪽은 연패 구간이 길어 훨씬 깊이 빠진다.
낙폭을 싣지 않으면 이 둘이 같은 계획으로 보인다.

**셋째, 이것이 Phase 6 백테스트가 낼 지표(MDD)와 같은 축이다.** Phase 2 의 낙폭은 가정에서
나온 값이고 Phase 6 의 낙폭은 실제 캔들에서 나온 값이다. 같은 이름의 값을 두 곳에서 내면
"가정대로 갔다면 이랬을 것" 과 "실제로는 이랬다" 를 나란히 놓을 수 있다.

## 딸린 결정 — 각 점은 직전 점이 아니라 초기 자본에서 계산한다

위 교환법칙은 **반올림이 새지 않을 때만** 성립한다. 자산 곡선의 각 점을 직전 점에 배수를
곱해 얻으면 점마다 센트 반올림이 끼고, 그 오차가 거래 수만큼 쌓인다.

1000 USDT 에 배수 1.03 을 다섯 번 적용한 값이다.

| 방식 | 결과 |
|---|---|
| 점마다 반올림 후 곱셈 | 1159.**28** |
| 초기 자본 × 누적 배수 | 1159.**27** |

5 거래 만에 1센트가 벌어진다. 100 거래면 더 벌어지고, 그러면 순서만 다른 두 경로의 최종
자산이 갈라진다. 그렇게 갈라진 값은 복리의 성질이 아니라 **반올림의 잔재**인데, 도구는
그 둘을 구분해 보여주지 못한다.

그래서 누적 배수는 `MathContext.DECIMAL128` 로 들고 다니고, `Money` 로 스냅하는 것은
각 점을 만들 때 한 번뿐이다. `Money.times(BigDecimal)` 이 그 지점이다.

## 한계

- **낙폭은 곡선의 점 사이에서만 잰다.** 실제로는 한 거래 안에서 손절가까지 밀렸다 익절로
  끝나는 일이 있고, 그 왕복은 이 모델에 없다. 여기서 나오는 낙폭은 **실제보다 얕다.**
  거래 내부를 보려면 캔들이 필요하고 그것은 Phase 6 이다.
- **승률과 손익비가 거래마다 독립이고 일정하다고 가정한다.** 실제 매매는 그렇지 않다 —
  추세장에서 몰아서 이기고 횡보장에서 몰아서 진다. 연속성이 있으면 실제 낙폭은 이 모델보다
  깊다. 이 도구의 숫자는 **낙관적인 하한**으로 읽어야 한다.
- 파산 확률을 내지 않는다. 고정 비율 사이징에서 자산은 산술적으로 0 이 되지 않아,
  "파산" 을 정의하려면 임의의 문턱값을 도입해야 한다. 대신 손실 확률과 최악 낙폭을 낸다.

## 철회 조건

**사이징이 고정 금액으로 바뀌면 이 ADR 의 전제가 사라진다.** 자산이 더해지는 모델에서는
순서가 최종 자산도 바꾸고, 그러면 "순서는 낙폭에만 나타난다" 는 문장이 틀린 말이 된다.

## 결과

- `EquityCurve.maxDrawdown()` 이 순서 의존성을 드러내는 유일한 지표다.
- API 응답 `MonteCarloResponse` 에 `medianMaxDrawdown` / `worstMaxDrawdown` 이 들어간다.
  800 USDT, 승률 45%, 손익비 2, 거래당 2%, 100 거래, 1000 시행에서 최종 자산은
  594.44 ~ 3980.53 으로 갈리고 최대낙폭의 중앙값은 14.92% 다.
- `Money.times` / `Money.minus` / `Money.percentOf` 를 추가했다. 반올림 정책이 값 객체 밖으로
  나가지 않게 하려는 것이다.
- 두 모듈이 같은 null 검사를 쓰게 되어 `PositionValues` 를 `common.domain.DomainValues` 로 올렸다.
