# ADR 012 — 청산가를 근사식에서 거래소 정확식으로 바꾼다

- 상태: 채택
- 날짜: 2026-08-21

## 맥락

Phase 1 은 청산가를 다음 근사식으로 냈다.

```
LONG:  liq = EP × (1 - 1/leverage + MMR)
SHORT: liq = EP × (1 + 1/leverage - MMR)
```

Phase 3 의 완료 조건은 **"Phase 1 청산가가 거래소 실제값과 오차 범위 내 일치"** 다.

근사식이 어디서 어긋나는지 보려면 청산 조건을 그대로 쓰면 된다. 격리마진 롱에서

```
증거금 - 손실 = 유지증거금
qty × EP/lev - qty × (EP - P) = qty × P × MMR - cumB
```

**유지증거금이 진입 명목가가 아니라 청산가 기준 명목가(`qty × P × MMR`)로 계산된다.**
미지수 `P` 가 양변에 있으므로 정리하면 나눗셈이 남는다.

```
LONG :  liq = [EP × (1 - 1/lev) - cumB/qty] / (1 - MMR)
SHORT:  liq = [EP × (1 + 1/lev) + cumB/qty] / (1 + MMR)
```

이것은 바이낸스가 공개한 공식과 같다.

```
LiqPrice = (WB + cumB - Side × Position × EP) / (Position × MMR - Side × Position)
```

근사식은 `1/(1 - MMR)` 을 `(1 + MMR)` 로 본 것, 즉 나눗셈을 곱셈 한 번으로 뭉갠 것이다.

## 결정

**정확식으로 교체한다.** 그리고 `MaintenanceMarginPolicy` 의 시그니처를
`rate()` 에서 `requirementFor(Money notional)` 로 바꾼다.

두 가지가 함께 바뀌어야 한다. 정확식에 `cumB`(유지증거금 공제액)가 등장하는데, 그 값은
포지션 크기에 따라 달라지는 구간표에서 온다. 인자가 없던 예전 시그니처로는 받아올 자리가 없다.

## 근거

**오차의 크기.** EP 60,000 / 10배 / MMR 0.4% / cumB 0 에서

| | 값 |
|---|---|
| 근사식 | 54,240.00 |
| 정확식 | 54,216.87 |
| 차이 | 23.13 (0.043%) |

비율로는 작다. 그러나 이 도구가 답하는 질문이 **"손절가를 어디에 둘 수 있는가"** 이고,
손절가가 청산가 너머면 계획을 거부한다. 거부·통과의 경계에 23 USDT 가 걸려 있다.

**방향도 문제다.** 롱에서 근사식은 실제보다 **높은** 청산가를 낸다. 즉 청산이 실제보다
가깝게 보인다. 안전한 쪽으로 틀린 것이라 넘어갈 수도 있었지만, 숏에서는 반대로 실제보다
**낮은** 값이 나와 청산이 멀게 보인다. 방향에 따라 틀리는 쪽이 갈리는 오차는 "보수적" 이라고
부를 수 없다.

**구간별 MMR 이 함께 필요한 이유.** BTCUSDT 는 명목가 50,000 을 넘으면 MMR 이 0.4% 에서
0.5% 로 오른다. 정확식만 도입하고 MMR 을 고정하면 큰 포지션의 청산가가 여전히 틀린다.
공식과 입력을 함께 고쳐야 완료 조건이 성립한다.

## 한계

**구간 선택은 진입 명목가로 한다.** 엄밀하게는 거래소도 청산가 기준 명목가로 구간을 고르므로
반복 계산이 필요하다. 그 결과 구간 경계 근처에서 우리 값과 거래소 값이 미세하게 갈릴 수 있다.
계획 단계의 도구이므로 진입 명목가 기준으로 충분하다고 본다. 실제 포지션을 열고 나서 오차가
문제가 되면 그때 반복 계산을 넣는다.

**"거래소 실제값" 의 정의.** 실제 포지션의 청산가를 거래소에서 읽으려면 계좌 권한이 필요하고
그것은 `scope.md` 밖이다. 그래서 검증 기준은 *바이낸스가 공개한 공식 + 공개된 구간표로 손으로
푼 값*이다. `LiquidationAgreesWithExchangeTest` 가 그 대입 과정을 테스트마다 적어 두고,
오차 허용치 없이 센트 단위 일치를 요구한다.

## 결과

- `PositionExposure`(방향, 평단, 수량, 레버리지)를 새로 두고 공식을 그 안에 둔다.
  넷을 한 자리에 모아야 공식만 따로 테스트할 수 있다.
- `MaintenanceMargin`(비율, 공제액) 이 정책의 반환 타입이 된다.
- Phase 1·2 의 청산가 기댓값이 전부 바뀌었다. 각 테스트에 새 값의 검산 과정을 주석으로 남겼다.
- `FixedMaintenanceMarginPolicy` 는 도메인 테스트용으로 남는다. 공식만 검사하려면 MMR 을
  직접 주입해야 한다 — 구간표를 끌고 들어오면 공식이 틀렸는지 구간 선택이 틀렸는지
  구분되지 않는다. 이것은 ADR 008 이 이미 정한 방침이다.
