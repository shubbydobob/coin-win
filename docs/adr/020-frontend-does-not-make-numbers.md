# ADR 020 — 프론트는 숫자를 만들지 않는다

- 상태: 채택
- 날짜: 2026-08-22

## 맥락

Phase 8 이 더하는 것은 이미 있는 계산을 화면에 놓는 일뿐이다. 그런데 화면을 짓다 보면
숫자를 하나 더 만드는 것이 언제나 더 쉽다 — 손익비를 두 값으로 나누는 편이 요청을 한 번 더
보내는 것보다 짧고, 표를 예쁘게 만들려면 자릿수를 줄이고 싶어진다.

그렇게 만든 수가 위험한 이유는 **틀려서가 아니라 갈라지기 때문**이다. 같은 규칙이 자바와
타입스크립트 양쪽에 존재하는 순간, 한쪽만 바뀌는 날이 반드시 온다. 그날 화면은 여전히
그럴듯한 수를 보여 준다.

명세(`docs/spec/phase8-frontend.md` § 13.4)는 이 ADR 을 **구현이 끝난 뒤에** 쓰기로 했다.
유혹받은 자리가 없었다면 규칙이 자명했던 것이므로 ADR 이 필요 없다고 봤기 때문이다.
**유혹받은 자리가 넷 있었다.**

## 결정

**화면에 나오는 모든 수는 응답 본문에 그대로 있던 수여야 한다.** 경계는 "그 수가 도메인
규칙의 결과인가" 다. 규칙은 사람이 아니라 ESLint 가 지키고, 규칙이 실제로 발동하는지는
`frontend/eslint-fixture/` 의 위반 파일이 증명한다.

## 유혹받은 네 자리

### 1. 경고 문구에 기준값을 적고 싶다 — 막았다

`weakRiskReward` 는 손익비가 1.5 미만이라는 뜻이다. 화면에 "손익비가 1.5 미만이다" 라고
쓰는 것이 친절해 보인다. 그러나 그 1.5 는 `PositionPlan.MINIMUM_RISK_REWARD` 에 있고,
백엔드가 기준을 바꾸면 **화면만 옛 숫자를 말한다.**

"손익비가 기준에 못 미친다" 로 쓰고 서버가 낸 손익비를 옆에 둔다. **도메인의 상수도 도메인의
문장과 같다** — § 7 이 오류 문장을 짓지 말라고 한 것과 같은 뿌리다.

### 2. 빈 칸을 0 으로 채우고 싶다 — 막았다

`Number("")` 는 `0` 이다. 그대로 두면 잔고를 비운 요청이 **"잔고 0"** 이라는 있지도 않은
값을 서버에 보낸다. 빈 칸은 `NaN` → `null` 로 실어 보내고 서버가 "누락된 필드" 로 답한다.
화면이 자체 검증 문장을 지으면 그것이 두 번째 사본이다.

### 3. 표시 자릿수는 사본이 맞다 — 조건부로 허용했다

JSON 숫자는 스케일을 싣지 못한다. 서버가 `60000.00` 을 보내도 도착하는 것은 `60000` 이므로
`format/` 이 자릿수를 되살린다. 이것은 `conventions.md` 가 값 객체에 모아 둔 정책의 두 번째
사본이 **맞다.**

그럼에도 안전한 이유는 이 사본이 *표시 자릿수*만 갖고 *반올림 정책*은 갖지 않기 때문이다.
계산이 없으므로 갈라질 값이 없다. 그 전제를 지키는 규칙이 하나 있다 — **스케일을 줄여서
표시하지 않는다.** 줄이는 순간 브라우저가 반올림을 하게 되고 위 문장이 거짓이 된다.

기간(`PT26H30M` → `1일 2시간 30분`)도 같은 규칙 아래 있다. 0 이 아닌 단위를 하나도
빠뜨리지 않는 이유는, `8시간` 이 8시간 55분을 뜻하게 되는 순간 그것이 자릿수를 줄인 것과
같은 종류의 거짓말이기 때문이다.

### 4. 파라미터 기본값은 사본처럼 보인다 — 허용했다

백테스트 설정의 기본값(피벗 5 / 군집 0.5 / 터치 2 / ATR 14)은 도메인의
`ZoneSettings.standard()` 에도 있다. 사본으로 보이지만 성질이 다르다 — **화면에 보이는 수가
곧 요청에 실리는 수**이므로 사용자가 보는 것과 서버가 받는 것이 언제나 같다. 갈라질 값이
없다.

1 번과의 차이가 이 절의 요점이다. 판정 기준(1.5)은 **화면에 보이지 않는 규칙**이라 갈라져도
알 수 없다. 입력 기본값은 화면에 그대로 떠 있고 사용자가 고칠 수 있다.

## 규칙을 지키는 것

| 금지 | 예외 |
|---|---|
| `toFixed` `Math.round` `Math.floor` `Math.ceil` `new Intl.NumberFormat` | `src/format/**` |
| `Number()` `parseFloat` `parseInt` | `src/form/**` |
| feature 디렉터리 간 직접 import | 없음 |

**초안의 금지 목록이 실제 반올림 도구를 빼먹고 있었다.** 표에 `toFixed` 만 있었는데
`format/` 이 실제로 쓰는 것은 `Intl.NumberFormat` 이다. 그대로 뒀으면 규칙이 가장 흔한
반올림 경로를 그냥 통과시킨다. **화면을 하나 짓고 나서 규칙을 정하라는 순서가 값을 한
자리다** — 규칙을 쓸 때 상상한 도구와 코드가 쓰는 도구가 달랐다.

**두 예외는 대칭이 아니다.** `format/` 은 반올림도 파싱도 한다 — 기간은 문자열로 오는
응답이라 읽으려면 파싱이 필요하다. `form/` 은 반올림이 금지된 채로 남는다. 기준은 **출력이
가는 곳**이다. `format/` 은 문자열만 내고 화면으로만 가지만, `form/` 에서 나온 수는 그대로
요청 본문에 실린다.

## 결과

- 화면 코드에 도메인 계산이 하나도 없다. 손익비·청산가·평단·집계는 전부 응답에 있던 값이다.
- 값이 없는 것과 0 이 구별된다 — `profitFactor: null` 은 `—` 이고 `PT0S` 는 `0초` 다.
- 규칙이 발동하는 것을 픽스처가 매 빌드 증명한다. 통과하는 것처럼 보이면서 아무것도 매칭하지
  않는 린트 규칙은 남지 않는다.

## 대안

**전부 서버에 묻기.** 표시 자릿수까지 서버가 문자열로 내면 사본이 0 이 된다. 그러려면 응답의
`number` 를 전부 `string` 으로 바꿔야 하고, 그것은 OpenAPI 계약과 모든 소비자를 바꾸는 일이다.
화면 하나 때문에 백엔드 계약을 바꾸지 않는다.

**규칙을 문서로만 두기.** Phase 0 이 ArchUnit 에 대해 이미 답한 것이다 — 규칙은 기억이 아니라
빌드가 지킨다.
