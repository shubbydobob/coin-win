# 지표 예측력 측정 파이프라인

대시보드에 뜨는 지표들이 **미래 가격 방향에 대해 실제로 예측력을 갖는지** 재는 로컬 연구
도구다. 신호를 만들지 않고 분포를 잰다. **"예측력 없음" 이 유효한 결론이고, 그쪽이 기본
가정이다.**

앱과 분리돼 있다 — Gradle 빌드도 `check` 게이트도 이 디렉터리를 보지 않는다. 데이터는
`data/` 아래 SQLite 하나에만 쌓이고 어디로도 나가지 않는다.

## 지금 어디까지 됐나

## 돌리는 법

```powershell
cd research
python backfill.py            # 과거를 채운다. 중간에 죽어도 다시 돌리면 이어서 한다
python backfill.py --report   # 받지 않고 현재 상태만 본다
python collect.py             # 15분마다 수집. 계속 떠 있어야 한다
python collect.py --once      # 한 슬롯만 (확인용)
python test_guards.py         # 게이트가 실제로 막는지 본다
python crosscheck.py          # 덤프와 REST 가 같은 값을 주는지 맞댄다
```

**`collect.py` 는 계속 떠 있어야 한다.** 꺼져 있던 동안의 호가는 영영 없다. 나머지는 다시
켜면 메워진다. 윈도우에서는 작업 스케줄러에 등록하거나 터미널 하나를 계속 열어 둔다.

Phase 1 은 표준 라이브러리만 쓴다. `requirements.txt` 는 Phase 2 부터 필요하다.

**REST 파생 통계(`/futures/data/*`)는 정확히 31일만 준다.** 30.92일 전은 오고 31.00일 전은
`-1130` 이다. 그래서 백필은 REST 가 아니라 덤프를 본다.

**`futures/data` 계열은 가중치 헤더를 주지 않는다.** 소비량을 관측할 수 없고, Phase 0 조사
중 실제로 `-1003` IP 차단을 맞았다. 이 계열을 부르는 자리는 전부 간격을 둔다.

**호가는 어떤 덤프로도 우리 정의로는 못 얻는다.** `bookTicker` 덤프는 2024년 봄에 끊겼고,
`bookDepth` 덤프는 2023-01 부터 있지만 **±1~5% 누적 물량**이라 우리 화면의 20단 두께와 다른
양이다. 이어 붙이면 그 지점에서 정의가 바뀌는 계열이 되므로 붙이지 않았다.

## 코드가 지키는 규칙

**결측은 채우지 않는다.** 없으면 NULL 이다. forward-fill 은 분석 단계에서 명시적으로 고른다.

**룩어헤드를 세 겹으로 막는다.**

1. 가격은 슬롯 시각에 **이미 닫힌** 1분봉에서 온다. 슬롯 15:00 은 `open_time` 14:59 인 봉이다.
2. 파생 통계는 5분 격자에서 **시각이 정확히 같은 것**만 쓴다. 이웃 격자를 끌어오지 않는다.
3. 호가는 경계 **직전**에 읽고 읽은 시각 이상인 첫 슬롯에 붙인다.

그리고 저장이 검사한다 — 어떤 `{지표}_ts` 도 `slot_ts` 를 넘을 수 없고, 조립 뒤에 전수로 다시
묻는다. `test_guards.py` 가 그 검사들이 **실제로 막는지**를 위반 픽스처로 증명한다
(`archFixture` 와 같은 태도다).

**펀딩비만 마지막 값을 끌어온다.** 8시간마다 갱신되므로 "슬롯 이하의 마지막 확정값" 이 그
시점에 실제로 알려진 값이다. 채워 넣기가 아니라 계단 함수를 읽는 것이다.

## Phase 3 의 판정 기준 (`config.py` 에 상수로 박혀 있다)

분석 후에 기준을 정하면 결과에 맞춰 기준이 움직인다. 그래서 미리 적어 둔다.

- 표본 **1,000행 미만이면 어떤 결론도 내지 않는다.** "데이터 부족" 한 줄만.
- BH 보정 후 **p ≥ 0.05 면 예측력 없음으로 확정.** "가능성 있음" 은 쓰지 않는다.
- 승률이 기준선 대비 **+3%p 미만이면 실용적으로 무의미**로 분류한다.
- 평균 MAE 가 실제 청산 거리를 넘는 분위는 **승률과 무관하게 사용 불가**.
- 상관 **0.7 이상은 독립 증거로 세지 않는다.** 클러스터당 대표 하나만 유효 테스트로 센다.

## 실측 (2026-08-25 백필 결과)

209,725행, 2020-09-01 00:00 ~ 2026-08-25 15:00 (UTC). SQLite 957MB.

| 지표 | 채워진 비율 |
|---|---|
| 선물가 · 현물가 · 펀딩비 | 100.0% |
| 미결제약정 | 99.9% |
| 롱숏 계정 비율 | 99.0% |
| 테이커 매수/매도 비율 | 94.0% |
| 상위 계정 수/포지션 비율 | **85.2%** |
| 호가 넷 | 0.0% (오늘부터 쌓인다) |

**상위 계정 비율의 구멍은 전부 2022년이고 원본이 비어 있다.** 2022-10-01 덤프의 행이 실제로
`...,125456.203,2435318175.775,"","",1.697,0.447` 이다 — 우리 파싱이 아니라 바이낸스가
그 기간 값을 안 냈다. 가장 긴 구간이 **2022-09-03 ~ 2022-12-14 (102일)** 이고 2022년 한 해의
87%가 빈다. **2022년은 하락장이므로 국면별로 나눠 보는 Phase 3-4 에서 이 지표는 하락장
표본을 거의 갖지 못한다.** 채우지 않았고 채우면 안 된다.

**덤프와 REST 는 같은 값이 아니라 가까운 값이다.** 겹치는 이틀(576격자)에서 상대 오차의
중앙값이 0.01~0.10%, 최대가 5.1%다. 그래서 REST 는 임시로만 쓴다 — 그 날의 덤프가 올라오면
백필이 덮는다(`ingest_log` 에 그 날이 없으므로 다시 받는다). 이 자가 치유가 실제로 도는지는
`ingest_log` 에 오늘 날짜가 없다는 것으로 확인했다.

## 정직하게 적어 둘 것

- **`LIQUIDATION_DISTANCE_PCT` 는 자리표시자다.** 10배 기준 대략치를 넣어 두었을 뿐이고
  Phase 3 전에 실제 값으로 바꿔야 한다. 슬리피지 기본값과 같은 자리다.
- **덤프와 REST 의 차이를 없애지는 못했다.** 크기를 재고(위 § 실측) 자가 치유를 확인했을
  뿐이다. 하루 이내의 최신 구간을 분석에 쓸 때는 그 구간이 REST 값일 수 있음을 기억한다.
- **구름·지지저항·매물대는 아직 스냅샷에 없다.** 계산은 자바 쪽이 트레이딩뷰 원문과 대조해
  확정한 것이고, 파이썬에 다시 구현하면 두 정의가 갈라진다. 1분봉을 원본 그대로 쌓아 두었으니
  Phase 2 에서 **자바 구현과 대조한 뒤에** 붙인다.
- **이 파이프라인은 매수·매도를 추천하지 않는다.** 분포를 재는 것이 전부이고, `scope.md` 의
  금지는 그대로 산다.
